AI 관제 구조도

사람이 목표를 주면, 작은 심판(관제)이 완료 정의를 동결하고 일꾼의 결과를 판정해 main에 올립니다. 관제는 계획·코딩을 하지 않습니다. 이 페이지는 코드 저장소에서 자동으로 생성됩니다.

계층

목표 처리 흐름

  1. 목표 입력
  2. 계약 초안·동결
  3. 판정기(테스트) 작성
  4. 구현
  5. 관문 판정
  6. 승격 또는 보류
  7. 원장 기록

같은 실패가 반복되거나 돈·의존성이 걸리면 사람 결정으로 넘어갑니다. 테스트를 쓴 모델은 그 목표를 구현하지 못합니다.

역할

관문 (Gate)결과물을 main에 올릴지 판정: 보호 경로 거절, 돈·의존성 보류, 통과하면 승격lib/gate/, lib/canon.js
계약·판정기목표의 완료 정의를 동결하고, 통과 여부를 가리는 테스트(센티널 포함)lib/contract.js, freeze.js, oracle.js
원장 (Ledger)일어난 일을 추가만 되는 기록으로 남기고 모든 상태를 거기서 파생lib/ledger.js, var/ledger.jsonl
스케줄러지금 무엇을 할지(한 번에 하나), 아무 일도 없으면 모델을 부르지 않음lib/tick.js, select.js
운영 규칙 (Policy)하루 한도, 역할 분담, 조용한 시간, 개선 자율도 같은 값lib/policy.js, config/policy.json
결정 창구사람이 답해야 할 일을 모아 보여 주고 답을 받음, 일일 요약lib/human.js, digest.js, aicp decide
일꾼 연결 (Adapters)Claude Code·Codex를 안전한 틀 안에서 실행lib/adapters/
개선 루프기록에서 개선 후보를 찾아 제안·시도·측정·채택 또는 되돌림lib/improve.js, lessons.js, aicp improve
일꾼 (Agents)실제로 계획·코딩·테스트 작성을 하는 모델 (서브에이전트 조율도 여기서)Claude Code, Codex CLI
프로젝트관제에 붙어 일을 받는 대상. 각자 정본 저장소를 가짐projects/<id>, var/canon/<id>.git
진화 시스템 (automaton)전략을 경쟁시켜 번 쪽을 살리는 제품 프로젝트. 관제의 일부가 아님, 자기 원장을 가짐프로젝트 automaton
운영 콘솔사람이 상태를 보고 입력하는 곳 (관제 밖)client/ 앱·서버
원격 뷰어폰·태블릿으로 이 PC 화면을 보고 조작client/remote/
진행 브리핑개발 진행을 읽기 전용으로 공개ai-engine-briefing 페이지
